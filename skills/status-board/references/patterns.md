# 拓扑与建模模式（抽象版，故意不含任何业务内容）

这里只画「形状」，节点名都是占位（步骤 1、数据 A …）。真实内容必须来自你面对的项目。
需要看某个字段的具体写法时，再去 `examples/` 找对应形状的范例。

## 先判断：你的流程属于哪种形状

```mermaid
flowchart TD
    Q1{"有几个入口 / 出口?"}
    Q1 -->|"1 进 1 出"| P1["P1 线性链"]
    Q1 -->|"多个入口汇到一处"| P2["P2 扇入"]
    Q1 -->|"一处分流到多个出口"| P3["P3 扇出"]
    Q1 -->|"中间分成互不依赖的几条再汇合"| P4["P4 并行支线"]
    Q2{"有「通过 / 拒绝」或「等人批准」的关卡吗?"}
    P1 --> Q2
    P2 --> Q2
    P3 --> Q2
    P4 --> Q2
    Q2 -->|"有"| P5["P5 关卡 + 旁路输出"]
    Q2 -->|"没有"| Q3{"有「失败了再来一遍」吗?"}
    P5 --> Q3
    Q3 -->|"有"| P6["P6 重试与迭代：图里不能画环"]
    Q3 -->|"没有"| Q4{"这个流程处理数据吗?"}
    P6 --> Q4
    Q4 -->|"不处理"| P11["P11 纯步骤流：只画 Pipeline"]
    Q4 -->|"处理"| P8["再按 P8 / P9 / P10 记录数据与要素"]
    P11 --> Q5{"要逐条审阅一批成果吗?"}
    P8 --> Q5
    Q5 -->|"是"| P12["P12 成果校验：独立的校验集，见下文"]
    Q5 -->|"否"| Q6
    P12 --> Q6{"流程用到了需要登记的资源吗?<br/>API Key / GPU / 磁盘…"}
    Q6 -->|"是"| P13["P13 资源管理：只登记来源，不存密钥"]
    Q6 -->|"否"| END["完成建模"]
    P13 --> END
```

## P1 线性链

```mermaid
flowchart LR
    A["步骤 1"] --> B["步骤 2"] --> C["步骤 3"]
```

- 记法：每个节点写 `role`（一句话作用）+ `desc`；边不用写 `label`，除非传递物值得说明。
- 常见误用：把一个步骤拆成十几个小节点。节点是读者想单独看进度/作用的单位，不是函数调用栈。

## P2 扇入（多个来源汇到一处）

```mermaid
flowchart LR
    S1["来源 1"] --> M["汇合步骤"]
    S2["来源 2"] --> M
    S3["来源 3"] --> M
```

- 记法：每个来源一个节点，各自可挂各自的任务；汇合步骤的 `reads` 列出全部上游数据。
- 一个来源缺失时：让汇合步骤的 `desc` 写清缺失时的处理方式，并在该来源节点的 `note` 里记下这次缺失。
- 注意：若有 `kind="run"` 任务的要素已流经下游，服务会按图的先后关系把上游节点推导为「已完成」，**覆盖** `sb.node` 手工置的 `skipped`。所以缺失要靠 `note` 和任务的 `message` 表达，不要只依赖手工状态。

## P3 扇出（一处分流到多个出口）

```mermaid
flowchart LR
    M["上游步骤"] -->|"出口 1"| O1["发布 1"]
    M -->|"出口 2"| O2["发布 2"]
```

- 记法：边的 `label` 写分流条件或传递物。出口之间若有先后（先 1 后 2），画成链，不要画成扇出。

## P4 并行支线再汇合

```mermaid
flowchart LR
    A["切分"] --> B1["支线 B1"]
    A --> B2["支线 B2"]
    B1 --> J["对齐"]
    B2 --> J
```

- 要点：一个**要素**同一时刻只位于一个步骤。要追踪「要素在并行支线上的位置」时，把「要素 × 支线」各当一个要素：

```mermaid
flowchart LR
    E["要素 X"] --> A["切分"]
    A --> U1["X/支线1 在 B1"]
    A --> U2["X/支线2 在 B2"]
    U1 --> J["汇合后 X 回到 对齐"]
    U2 --> J
```

- 「要素 × 步骤」矩阵里，不在某条支线上的格子显示「不经过」，是正确的，不是漏记。

## P5 关卡与旁路输出

```mermaid
flowchart LR
    G["关卡"] -->|"通过"| N["下游步骤"]
    G -.->|"拒绝（旁路）"| R["被拒记录"]
```

- 记法：关卡节点 `kind="gate"`。被拒的东西**要保存**并作为数据资产记录（`R`），写明拒绝原因去向。
- 人工审批：关卡节点 `status="running"` + `note` 写清「在等谁、等什么」，批准后置 `done`。

## P6 重试与迭代：图里不能画环

`validate` 会把环当成**错误**（布局需要无环）。需要表达「再来一遍」时三选一：

```mermaid
flowchart TD
    Q{"「再来一遍」是哪种?"}
    Q -->|"单个要素失败后重试"| A["不改图：要素 status 依次 failed → running → done，note 写原因"]
    Q -->|"同一步骤整体重跑"| B["不改图：任务置回 running；用 sb.milestone 记录为什么重跑"]
    Q -->|"流程本身改版后跑新一轮"| C["不改图：里程碑标注版本；若结构真的变了，改定义，时间线会保留旧版"]
```

## P8 数据：多个地址（副本）

```mermaid
flowchart LR
    D["数据 A"] --- L1["primary 主地址"]
    D --- L2["backup 备份"]
    D --- L3["mirror 镜像"]
    D --- L4["cache 缓存"]
```

- 记法：`locations` 每个副本一条：`label`、`role`、`storage`、`path`、`note`（同步方式/延迟）。**有几个地址就写几条，不要只写主地址。**
- `role` 取值：`primary backup mirror remote cache`。本机路径加 `auto_stat` 会统计大小并比对副本是否一致。
- 不知道备份在哪就不要写；用 `note` 或 `processing` 注明「备份位置待确认」。

## P9 数据血缘（加工关系）

```mermaid
flowchart LR
    X["数据 A"] -->|"加工过程 1"| Y["数据 B"]
    Y -->|"加工过程 2"| Z["数据 C"]
    W["外部数据 W"] -.->|"仅对照使用"| Z
```

- 箭头上写**加工过程**（动词短语），不是「→」。一份数据被多个下游使用就画多条边。
- `processing` 只补图和 Pipeline 表达不了的：被谁读过、做过哪些一次性处理。

## P10 要素规模：怎么上报「哪个要素到了哪一步」

```mermaid
flowchart TD
    Q{"要素有多少个?"}
    Q -->|"≤ 约 50 且想看每一个"| A["sb.item 逐个上报（矩阵里每行一个要素）"]
    Q -->|"50 ~ 500"| B["逐个上报也可以，但只上报有变化的，别每秒全量"]
    Q -->|"> 200 / 不关心个体"| C["sb.task(step_counts=...) 每次传完整快照"]
    A --> N["快照里各步骤数量之和 = 总要素数"]
    C --> N
```

- `step_counts` 是**整体替换**：每次必须传完整的各步骤数量，不是增量。
- 上限：items 最多 500 个。

## P11 纯步骤流（不处理数据）

```mermaid
flowchart LR
    A["步骤 1"] --> B["步骤 2"] --> C["人工关卡"] --> D["步骤 3"]
```

- 不需要数据图，节点也不用 `reads/writes`；状态用 `sb.node("pipelines", gid, nid, status=..., note=...)`，有耗时的步骤再挂普通任务。

## P12 成果校验：怎么建一个校验集

```mermaid
flowchart TD
    A["拿到一批要审的成果<br/>（模型生成的 / 清洗出来的 / 标注的…）"] --> B{"一行一个 JSON 对象吗?"}
    B -->|"否"| B1["先转成 jsonl：sb.review_rows(rows, 路径)"]
    B1 --> C
    B -->|"是"| C["放进资源目录（SB_ASSETS_DIR）"]
    C --> D["写 reviews 定义<br/>source / fields / rules / from / description"]
    D --> E["sb.py validate"]
    E -->|"有警告"| D
    E -->|"通过"| F["打开 #/review/id：先看规则自动检查的统计"]
    F --> G["按「规则不通过」视图优先人工复核"]
    G --> H["再抽样看「规则通过」的，确认规则没漏"]
    H --> I["sb.milestone 记录本次校验结论"]
```

**fields 怎么选**

```mermaid
flowchart TD
    Q{"这条成果要让人看什么?"}
    Q -->|"只是一段文字"| T["type = text / long（长文本）"]
    Q -->|"前后两个版本，想看改了什么"| D["type = diff，a 和 b 各指一个字段"]
    Q -->|"附带图片 / 音频 / 视频"| M["type = image / audio / video<br/>值是资源目录内相对路径"]
    Q -->|"结构化对象"| J["type = json"]
```

**rules 怎么写**

```mermaid
flowchart LR
    A["我担心的坏样本是哪几类?"] --> B["每一类写成一条规则"]
    B --> C{"能用 op 表达吗?"}
    C -->|"能"| D["自动规则：error 或 warn"]
    C -->|"不能（语义对不对、好不好看）"| E["留给人工标记；在 description 里写清判定标准"]
```

- 规则只是**帮人把注意力放对地方**，不替代人工判断：规则通过的样本也要抽样看，确认规则没有漏掉。
- 没把握的统计口径别写进规则（比如"回答是否正确"），交给人工标记，并在 `description` 写清判定标准。
- 想表达"字段可以没有，但有就必须满足某条件"：拆成两条规则，不要靠一条规则同时表达。
- `unique` 对大文件会占内存（上限约 50 万个值），只对确实需要去重的字段用。

## P13 资源管理：登记什么、怎么处理密钥

```mermaid
flowchart TD
    Q{"要登记的是什么?"}
    Q -->|"一把 API Key / 令牌"| K["kind = apikey<br/>只登记 secret_ref、额度、过期，不存密钥"]
    Q -->|"一台 GPU / CPU 主机"| C["kind = gpu / cpu<br/>count + access；本机的加 probe=local"]
    Q -->|"一块盘 / 挂载点"| D["kind = disk<br/>path + capacity_bytes；备份用 replica_of 指向主盘"]
    Q -->|"一个对内服务入口"| S["kind = service<br/>endpoint + auth_ref 指向它用的 Key"]
    Q -->|"都不是"| O["kind = other"]
```

**手里有一个密钥时，怎么登记**

```mermaid
flowchart TD
    A["拿到一个密钥"] --> B{"它现在存在哪?"}
    B -->|"环境变量里"| E["secret_ref = {env: 变量名}"]
    B -->|"某个文件里"| F["secret_ref = {file: 绝对路径}<br/>并确认文件权限是 600"]
    B -->|"团队密钥库里"| V["secret_ref = {vault: 条目名}"]
    B -->|"只在我手里，哪都没存"| N["先把它存到上面三处之一，再登记<br/>不要为了登记而把它写进任何文件"]
    E --> R["写 resources 定义（只有来源，没有内容）"]
    F --> R
    V --> R
    N --> R
    R --> T["sb.py validate：不应有任何密钥相关的错误"]
```

> 如果 `validate` 或写入报「疑似密钥」：说明某处出现了密钥内容。**先去源头删掉它**（并视情况轮换密钥），再重写定义。不要想办法绕过检测。

**静态信息与动态信息分开存**

```mermaid
flowchart LR
    A["定义 resources/池.json<br/>是什么 · 怎么取 · 额度多少 · 谁负责"] -->|"很少变化"| P["资源池页面"]
    B["用量 usage/池.json<br/>已用额度 · 谁占了多少 · 状态覆盖"] -->|"sb.resource 持续上报"| P
    C["本机探测 probe=local<br/>GPU 逐卡 · CPU 负载 · 磁盘用量"] -->|"后台线程 · 5 秒缓存"| P
    P --> W["首页「需要关注」<br/>异常 / 需关注的资源"]
```

- **分配是整体替换**：每次上报当前完整的占用清单，释放就是上报时去掉那一项。
- **别的机器的 GPU**：看板不会主动连远程地址。在那台机器上跑脚本，把 `used` / `metrics` 通过 `sb.resource` 报上来（远程上报用 `SB_URL`）。
- 资源不再使用：先把 `state` 置为 `revoked` / `disabled` 留痕，确认无人引用后再从定义里删除（删除会进入时间线）。

## 任务生命周期

```mermaid
stateDiagram-v2
    [*] --> queued: 创建
    queued --> running: 开始
    [*] --> running: 直接开始
    running --> running: 上报进度 / 心跳
    running --> done: 完成
    running --> failed: 出错
    running --> cancelled: 取消
    failed --> running: 重试
    done --> [*]
    cancelled --> [*]
```

`running` 超过 `stale_after` 秒无上报，页面标「疑似停滞」（不改变真实状态）。
